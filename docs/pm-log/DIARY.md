# Pulsar 决策日记

面试时按时间正序讲：先用户与非目标，再权限模型，再双含义命名，再 sleeve 拆分。每条都能回答「你砍掉了什么」。

---

## D001 · 用户与做成标准

- **问题：** 先做私人印钞机，还是按可开源产品做？
- **选项：** 只服务自己 / 第一天多用户 / 自己当超级用户但架构按开源标准。
- **拍板：** 自己当超级用户；文档、评测、默认安全按开源产品。
- **预期收益：** 面试能讲 dogfood 与 GTM 的冲突处理；clone 用户不会一上来实盘。
- **事后收益：** （待填）clone 无 key 能否 60 秒跑通。

## D002 · 第一条实盘闭环

- **问题：** 先做哪条资产？
- **选项：** A 股 / 美股 / BTC / 期货。
- **拍板：** Binance `BTC/USDT` 现货做实盘主线；美股与美股期货用 IBKR 从纸交易并行，不后置。
- **预期收益：** 24h 数据利于自迭代；IBKR 一条链覆盖股票+期货。
- **事后收益：** （待填）纸交易三 sleeve 是否真能独立记账。

## D003 · 实盘权限

- **问题：** Agent 能自动下真单吗？
- **拍板：** 限额内可自动；越界停机并通知；改限额必须人确认。LLM 不直接下单。
- **预期收益：** 高风险 side effect 有代码级控制，而不是 prompt。
- **事后收益：** （待填）kill switch 在 UI 与 CI 是否一次都没被绕过。

## D004 · 决策层用 Jev 形接口

- **问题：** 每个小判断都让大模型写 JSON 吗？
- **拍板：** DecisionPort 先做 `choice/score/noul`；无 Key 用规则顶上。门控阈值 code-only。
- **预期收益：** 以后接 TypeSafe 不用推翻循环。
- **事后收益：** （待填）接真 Jev 时改了几处调用点。

## D005 · 因子先验用 RSI 指标族

- **问题：** 让模型任意挖因子，还是限制搜索空间？
- **拍板：** 只在相对强弱指标族内挖；必须打败 `RSI(14)` 基线。
- **预期收益：** 可解释、可证伪、降低过拟合。
- **事后收益：** 合成盘上噪声对照已被拒绝；真实行情是否仍有效待填。

## D006 · 命名：RSI 与递归自我改进不许混用 · 2026-10-20

- **问题：** RSI 既是量化指标，又常被当成 Recursive Self-Improvement 的缩写。界面和代码一旦混用，用户会以为「自我改进」是再画一条 RSI 线。
- **选项：** 全部叫 RSI / 全部回避指标 / **界面透指标，自我改进一律全写**。
- **拍板：**
  - 产品和界面：该透 RSI 指标就透（周期、超买超卖、因子榜上的 RSI 值）。
  - 递归自我改进只留在开发侧与因子自进化；对外和对内开发文案都写全称。
- **预期收益：** 用户把 Pulsar 当交易产品时看见的是指标；面试时能分清「策略对象」和「harness 对象」。
- **事后收益：** （待填）UI 文案是否还出现缩写混淆。

## D007 · 一个产品，三个 sleeve，因子不混用 · 2026-10-20

- **问题：** BTC、美股、期货能不能共用一个因子？还是 Pulsar 只是外壳、下面三套完全独立的策略？
- **选项：**
  1. 一个因子打三个市场（硬跨市场门控）。
  2. 三个互不相干的机器人。
  3. **一个 Pulsar 大策略（同一套晋升协议与递归自我改进），按方向自动拆成 sleeve，因子按 (因子, sleeve) 晋升。**
- **拍板：** 选 3。混用因子不可行：交易时段、费率、杠杆、拥挤度都不同。统一的是协议，不是仓位，也不是同一组信号权重。
- **预期收益：** 比特币上的 RSI(2) 可以晋升，同时在 MES 上被拒绝，这是正确行为。风险账本已经隔离，晋升键也要隔离。
- **事后收益：** （待填）是否出现「一个因子在 BTC 赚钱就误开美股仓」的事故。

## D008 · 冻结核 · 2026-10-20

- **问题：** 递归自我改进可以改哪里？
- **拍板：** 可改研究 harness。不可改限额、kill switch、live 双开关、下单。CI 锁死。
- **预期收益：** 自我改进不会变成自我授权。
- **事后收益：** （待填）外环是否试过 patch `risk/` 并被测试拦住。

## D009 · Grok 运行预算与三种外环跑法 · 2026-10-20

- **问题：** 隔夜云电脑不能开无限循环。
- **拍板：** 必须有墙钟、轮次、费用/token 上限。跑法三档：节约（单优化点 + 单 sleeve）、分块（一块模块或一个 sleeve）、全局（全 sleeve，但仍受预算且默认一步一改）。
- **预期收益：** 能针对「只改记忆 top-k」这种点单独跑，不必每次全市场进化。
- **事后收益：** （待填）节约档是否真能在预算内给出可回滚的 harness 版本。
